# Tasks: Desktop Apps and Automated Releases

**Input**: Design documents from `/specs/003-desktop-apps-releases/`

**Prerequisites**: plan.md, spec.md, research.md (**R-D-n**), data-model.md, contracts/ (`desktop-bridge.md`, `release-pipeline.md`), quickstart.md; governed by `.specify/memory/constitution.md`.

**Tests**: REQUIRED. The constitution requires a Playwright end-to-end test for each P1 and P2 story, a plaintext-leak scan, and test-first development for logic with rules (header parsing, path mapping, IPC validation, update-mode decision, desktop-state sanitising, release rules). Within each story, test tasks come first and MUST fail before the matching implementation.

**Organization**: Tasks are grouped by user story (spec priorities P1, P2, P3) so each can be implemented and tested independently once Foundational is done. The plan's own phase numbers (0-6) map as: plan 0 = Phase 1 here, plan 1 = Phase 3 (US1), plan 2 = Phase 4 (US2), plan 3-4 build and release = Phases 3 and 6, plan 5 = Phase 5 (US3), plan 6 = Phase 7 (US5).

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependency on incomplete tasks)
- **[Story]**: User story label (US1...US5). Setup, Foundational and Polish tasks have none.
- `Depends on Txxx` marks an explicit dependency beyond phase order.
- `Refs:` lists the spec requirements (FR-/SC-), research items or constitution principles each task serves.
- **Owner** marks a task only the project owner can do (accounts, secrets, approvals). They are not code and an engineer must not fake them.

## Path Conventions

New: `apps/desktop/`, `packages/platform/`. Changed: `apps/web/src/{adapters/platform,ui/settings,ui/shell,ui/i18n/messages,sw}/`, `.github/workflows/`, `scripts/`, `eslint.config.js`, `turbo.json`, `vitest.workspace.ts`, `docs/`, root release files. **No task changes** `packages/core`, `packages/crypto`, `packages/protocol`, `apps/server` or any existing Core Worker command or query (FR-002, FR-005). The only permitted addition is a read-only "quiesce" call in `apps/web/src/worker/` (T068), and only if one does not already exist.

## Scope Note

Recommended first milestone: Phases 1-4 (Setup, Foundational, US1 and US2, the P1 stories) produces installable, safe, unsigned desktop builds. Phase 5 (US3) and Phase 6 (US4) are P2; Phase 7 (US5) is P3. **No release can publish until the external security review is complete** (`docs/security-review/status.md`, currently *pending*); everything up to Phase 6 is verified without publishing.
