# Languages

Cashfold is shown in English, Ukrainian (`uk`) and Polish (`pl`). Arabic (`ar`) has right-to-left layout and falls back to English words until it is translated. This page is for people who change the text or add a language. The decisions are in [ADR-0011](adr/0011-languages-and-catalogue-loading.md) and `specs/004-ukrainian-polish-languages`.

## How a language is chosen

1. If the person picked one (on the sign-up page while creating the account, or later in Settings → Appearance; no other page offers the choice), that language is used. The choice is stored on the device only (`language` in the `cashfold.ui` preferences), never synced and never sent to the service.
2. Otherwise the first of the browser's preferred languages that we support (`pl-PL` and `uk-UA` count as `pl` and `uk`).
3. Otherwise English.

"Automatic" in Settings goes back to rule 2. The pages shown before sign-in other than sign-up (home, unlock, recover, add device) only show the saved or detected language. The desktop app also tells its shell which language is shown, so its menu follows; its start-up error dialog follows the operating system's language, because no window exists yet.

## Where the text lives

| What                                                          | Where                                                                                                       |
| ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| English (the source of truth, and the fallback for every key) | `apps/web/src/ui/i18n/messages/en.json`, plus the error messages in `apps/web/src/ui/errors/catalogue.ts`   |
| Ukrainian, Polish                                             | `apps/web/src/ui/i18n/messages/uk.json`, `pl.json` (the error messages are ordinary `error.*` keys in them) |
| Names of the languages, the list people can pick from         | `LANGUAGE_NAMES` in `apps/web/src/ui/i18n/i18n.ts` (each in its own language, never translated)             |
| Desktop menu and start-up dialog                              | `apps/desktop/src/main/menu-labels.ts`                                                                      |
| Terms that must be used the same way everywhere               | `specs/004-ukrainian-polish-languages/contracts/glossary.md`                                                |

English is part of the main bundle. Ukrainian and Polish load when first needed; they are separate files that the offline worker has already stored.

## Adding or changing a message

1. Add the key to `en.json` (ICU MessageFormat, `{name}` placeholders, `plural` and `select` where the text depends on a count or a value).
2. Add the same key to `uk.json` and `pl.json`. A count needs **all four forms** in both languages: `one`, `few`, `many`, `other`. Add `=0` or `=1` for a wording that only fits exactly 0 or 1, because `one` also matches 21, 31 and so on in Ukrainian.
3. Run `pnpm --filter @cashfold/web test`. `catalogue-complete.test.ts` fails, naming the language, the key and the rule, if a key is missing or extra, a message does not parse, the placeholders differ from English, a plural lacks a form, a value is left identical to English (add the key to `IDENTICAL_ALLOWED` in that test only for names, codes and words that are really the same), or a default category lacks its `starter.category.*` name.
4. Never put text in a component directly. `e2e/pseudo-walk.spec.ts` walks the app in the pseudo-locale `en-XA` and fails on any English word that did not come through the catalogue.

Use the terms in the glossary. Words for the same thing must not vary between screens.

## Money, dates and names

Amounts are exact integers in minor units in every language. What a person types is read with the language's separators: `1 234,56`, `1234,56` and `1234.56` are all accepted in Polish and Ukrainian, with an ordinary, no-break or narrow no-break space; an entry that mixes a dot and a comma is refused. `core` knows nothing about languages.

`core` orders names by character code on purpose. Lists ordered by name (payees, tags) are re-ordered for display with `Intl.Collator`, so `Ł` follows `L` and `Ї` follows `І`. Searching ignores case and accents, so `lodz` finds `Łódź`.

The names the app creates for a new person (the personal Fold, the default categories) are written in the language chosen at that moment and are theirs from then on. CSV exports keep fixed English column names and dots for decimals, so other programs can read them.

## Adding a language

1. Add its code to `LOCALES` and `LANGUAGE_NAMES` in `i18n.ts` and to `LANGUAGE_CHOICES` in `ui/prefs/schema.ts` (and the preferences schema in `specs/002-ux-redesign-catalyst/contracts/preferences.schema.json`).
2. Add `messages/<code>.json` and a case for it in `loadCatalogue`.
3. Add it to `SHELL_LANGUAGES` in `packages/platform/src/schemas.ts` and to `menu-labels.ts` if the desktop app should follow it.
4. Add its fonts' letters if they are not in the bundled Ubuntu faces.
5. Have a native speaker review it against the glossary.

## Review

The Ukrainian and Polish text was drafted before native-speaker review and is offered from the first release; one native speaker per language reviews every screen within one release cycle, and their corrections ship as ordinary updates (spec SC-007).
